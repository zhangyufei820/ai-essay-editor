# New API 人民币计费硬规则

本文件是隔离 New API 的计费、定价、余额、退款和月卡业务口径。任何后台兼容字段、供应商报价或历史数据都不得改变这条规则。

## 唯一业务币种

- 所有给用户展示的价格均为人民币，符号为 `¥`，币种代码为 `CNY`。
- 所有实际计费、余额扣减、退款和补扣均按人民币核算。
- 所有月卡价格、月卡可消费额度和月卡消费记录均按人民币核算。
- 后台出现的 `USD`、美元基准价格或美元兼容字段只允许作为计算中间量，不是用户价格，也不是用户账务币种。
- `VIP 旧版 ¥500 月卡` 的价格定义是人民币 `¥500`，不是 `500 USD`。

## 生产换算基线

生产基线参数：

```text
QuotaPerUnit = 500000
USDExchangeRate = 7.3
```

内部 quota 与人民币之间只能使用以下公式：

```text
人民币金额 = quota / QuotaPerUnit * USDExchangeRate
quota = 人民币金额 / USDExchangeRate * QuotaPerUnit
```

代入当前参数：

```text
人民币金额 = quota / 500000 * 7.3
quota = 人民币金额 / 7.3 * 500000
```

金额转换为整数 quota 时，必须使用现有业务路径规定的舍入方式，并在用户展示时以人民币金额复算校验。不得把人民币价格直接乘 `QuotaPerUnit`，也不得重复乘除 `USDExchangeRate`。

## 后台兼容字段

固定人民币价格写入以美元为基准的兼容字段时，必须先且只转换一次：

```text
后台兼容价格 = 人民币标价 / USDExchangeRate
扣费 quota = 后台兼容价格 * QuotaPerUnit * 分组倍率 * 其他业务倍率
```

复核最终人民币金额：

```text
最终人民币金额 = 扣费 quota / QuotaPerUnit * USDExchangeRate
```

非 `tiered_expr` 的动态 token 计费使用模型倍率时，当前 New API 的基础输入价为每百万 token `2` 个后台兼容价格单位，因此：

```text
输入价（¥/M tokens） = ModelRatio * 2 * USDExchangeRate * 最终分组倍率
输出价（¥/M tokens） = 输入价 * CompletionRatio
```

配置为 `tiered_expr` 的模型必须以表达式中的人民币目标价为准，不能再用 `ModelRatio` 页面公式倒推实际价。表达式中的 `p`、`c`、`cr`、`cc` 分别代表输入、输出、缓存读取、缓存创建；基础档、长上下文档和最终分组倍率必须逐项核对。无论采用哪条路径，最终都必须以实际扣除的 quota 反算人民币复核，禁止页面只读 `ModelRatio` 而运行时走另一套表达式却不提示。

## 上游成本覆盖

- 上游返回的成本只能用于后台换算，不改变用户账务仍以人民币结算的规则。
- 只有在 `UPSTREAM_COST_BILLING_CHANNEL_CURRENCIES` 中明确列出的渠道才允许用上游成本覆盖网站零售价，格式为 `渠道ID:币种`，多项用逗号分隔，例如 `21:USD,24:CNY`。
- 白名单币种只允许 `USD` 或 `CNY`。渠道未列入、配置币种无效，或上游明确返回的成本币种与白名单不一致时，必须放弃成本覆盖并回退到网站人民币零售价；通用成本字段的币种只允许从该渠道白名单声明中取得。
- 生产默认白名单为空，即默认不信任任何供应商返回的成本字段。

## 月卡

月卡的 `price_amount` 和 `currency` 必须表达人民币价格，`currency` 必须为 `CNY`。月卡 quota 按人民币价格反算：

```text
monthly_quota = floor(月卡人民币价格 / USDExchangeRate * QuotaPerUnit)
```

当前基线下：

| 月卡价格 | monthly_quota | quota 反算人民币 |
|---:|---:|---:|
| ¥100 | 6,849,315 | ¥100.00 |
| ¥200 | 13,698,630 | ¥200.00 |
| ¥300 | 20,547,945 | ¥300.00 |
| ¥500 | 34,246,575 | ¥500.00 |
| ¥1000 | 68,493,150 | ¥1000.00 |

任何历史月卡如果 `currency != CNY`，或 quota 反算人民币与标题价格不一致，都属于数据异常，必须先保留快照，再通过可审计、可回滚的事务修正。

### 旧 VIP Claude 兼容权益

- `legacy_monthly_card_claude_enabled` 是用户级旧 VIP 兼容开关，默认关闭，不得因此向所有月卡用户开放 Claude。
- 开关仅在用户存在有效月卡时生效，并仅允许既有 Claude 文本模型从月卡扣费；视频、Grok 和其他非月卡模型仍按原规则处理。
- Claude 请求按网站人民币零售价的 `1x` quota 扣减，不享受新月卡文本价值赠送倍率。
- 成功消费日志必须同时记录 `billing_source=subscription`、实际 `subscription_id` 和 `legacy_monthly_card_claude_enabled=true`，便于逐请求审计。

## 修改与审计要求

任何涉及价格、倍率、quota、余额、退款、补扣或月卡的修改，必须同时完成：

1. 记录修改前的配置、账务流水和用户余额快照。
2. 同时复核用户展示价、运行时价格快照和最终扣费 quota。
3. 用上述公式把 quota 反算为人民币，并与标价逐笔核对。
4. 账务写入必须使用既有事务和幂等业务键，不得直接覆盖余额后不留流水。
5. 退款和补扣不得重复执行；失败重试必须能识别已经完成的操作。
6. 部署后验证生产参数、真实计费路径和用户可见人民币文案。
7. 审计报告统一使用人民币；若必须说明后台美元兼容值，必须同时标明它只是中间值。
